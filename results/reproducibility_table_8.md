Generated by `scripts/20_settings_table.py`; do not edit by hand. Every value is checked against the code or
records named in `reproducibility_table.csv` (columns `evidence_v1`, `evidence_v2`).

v1 = tag `v1-expert-eval` (backend, scrapers, Streamlit frontend). v2 = tag `v2.7-eval-frozen` (backend at `v2.7` (`c2980b8`), scrapers `c5527ef`; React frontend `1af17ba`), defined by `config/v2.7_freeze.json`.

`Scope` says how the paper may use a row: a *version difference*, a setting *shared* by both versions'
evaluations (ground rule 9: data corrections are not version differences), *reproducibility only*, or
*v2 evaluation instrumentation* (absent from production behaviour).

## Notes

- **Report and vote texts used in the evaluation:** Ground rule 9: the re-extraction is a data correction, applied to both versions' methods.
- **Name curation (recorrente, recorrido, relator, advogado → `*_curated`):** Confirmed by the author (DECISIONS 2026-09-27). The GPT-4o script in the backend (`utils/curateNames.py`, Azure OpenAI) is MongoDB-era and did not produce the v1 snapshot.
- **Corpus embeddings:** Selected in Phase 4.1 on a development half of the queries (results/a1_candidates_selection.json). Until the v2.2 freeze the stored vector was the compressed report's embedding alone.
- **Chat case summaries (hierarchical mode):** Evaluation-only context mode (Phases 6–7); production uses full_text.
- **Temperature:** The v2.5 freeze set the chat's temperature to 0; v2.6 selects a chat strategy that leaves it at the model default (DECISIONS 2026-10-12).
- **Projection:** Global by design in both versions: the map is refitted when the dataset is updated, never on filtering (the author, DECISIONS 2026-09-27). Checked on the pickled mapper at the tag: 1,537 × 768 training vectors; projected points land within ~0.2% of the map's span of their fitted positions whatever the subset.
- **UMAP parameters:** Selected in Phase 5.1 (results/a2_candidates_selection_2.json). Until the v2.2 freeze: n_neighbors 30, min_dist 0.01, the library's default 500 epochs, rows in the order of the input.
- **Candidate cases:** Until the v2.3 freeze the user selected every case by clicking on the map (the author, DECISIONS 2026-10-10).
- **Chat system prompt:** The rules were added to reduce statements that the cases do not support (Phase 6.1; v2.5 had the grounding rules and a rule preferring a short answer, at temperature 0).
- **Uploaded case (notice) given to the agents:** See results/agent_protocol.md: with an uploaded notice and no typed description, v2's legal searcher does not see the notice. Phase 8 supplies notices as uploads only, as users do (DECISIONS 2026-09-27).
- **Fact controls (v2.7):** Added after the v2.6 evaluation (Phase 8 improvement round, PHASE_8_SUMMARY).
- **Tool and parameters:** The plan lists Tavily for v2; v2 uses Google Search grounding (recorded in the v2.1 CHANGELOG entry).
- **Tokens and cost per request:** Measured on a local server calling the cloud APIs, one request at a time, not on production Cloud Run (Phase 9). Costs: the model calls the server logged, at Standard PayGo prices of `config/prices.yaml`; not counted: Google Search grounding in full mode ($14 per 1,000 queries; the queries are not recorded) and the embeddings of an upload (at most $0.0006).
